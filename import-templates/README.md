# เทมเพลตนำเข้าข้อมูล (Bulk import templates)

ไฟล์ Excel สำหรับกรอกข้อมูลทีละมากๆ แยกเป็น 5 ไฟล์ตามชนิดข้อมูล เรียงตามลำดับที่ต้องนำเข้า

| # | ไฟล์ | ปลายทาง | คอลัมน์ | จำเป็นต้องกรอก |
| --- | --- | --- | --- | --- |
| 1 | `import-template-companies.xlsx` | `public.companies` (ลูกค้า) | 9 | `name` |
| 2 | `import-template-contacts.xlsx` | `public.contacts` (ผู้ติดต่อ) | 9 | `first_name` |
| 3 | `import-template-sites.xlsx` | `public.sites` (ไซต์งาน) | 9 | `name` |
| 4 | `import-template-assets.xlsx` | `public.equipment` (Asset) | 14 | `site_name`, `name`, `asset_type`, `category` |
| 5 | `import-template-service-contracts.xlsx` | `public.service_contracts` (สัญญาบริการ) | 13 | `title`, `service_type`, `start_date` |

แต่ละไฟล์มี 3 ชีต

- **ข้อมูล** — กรอกจริงที่นี่ แถวที่ 1 เป็นหัวคอลัมน์ (ตรึงไว้ + มี filter) ช่องที่เป็นตัวเลือกมี dropdown ให้เลือก
- **ตัวอย่าง** — ตัวอย่างการกรอก 3–4 แถว ไว้ดูรูปแบบอย่างเดียว
- **คำอธิบาย** — อธิบายทุกคอลัมน์ ทั้งชนิดข้อมูล ค่าที่ยอมรับ และวิธีจับคู่ข้อมูล

สีหัวคอลัมน์

| สี | ความหมาย |
| --- | --- |
| 🟧 ส้ม | จำเป็นต้องกรอก ถ้าเว้นว่างแถวนั้นถูกข้าม |
| 🟨 เหลือง | ไม่บังคับ แต่ไฟล์อื่นใช้จับคู่ด้วยช่องนี้ เว้นว่างแล้วสายสัมพันธ์จะขาด (ปัจจุบันคือ `tax_id`) |
| 🟩 เขียว | เว้นว่างได้ |

## ลำดับการนำเข้า

ต้องเรียงตามหมายเลขในตารางข้างบน เพราะไฟล์หลังอ้างถึงข้อมูลที่ไฟล์ก่อนสร้างไว้

1. **ลูกค้า** — ตั้งต้นของทุกอย่าง
2. **ผู้ติดต่อ** — ผูกกับลูกค้า
3. **ไซต์งาน** — ผูกกับลูกค้า และผู้ติดต่อประจำไซต์ด้วย `contact_name`
4. **Asset** — ต้องผูกกับไซต์ที่มีแล้ว (`site_name`)
5. **สัญญาบริการ** — อ้างถึงลูกค้าและไซต์ ส่วนช่างต้องมีในระบบอยู่แล้ว (`technician_name`)

### การจับคู่ลูกค้า

ไฟล์ที่ 2, 3 และ 5 มีคอลัมน์อ้างถึงลูกค้า 3 ช่อง ตัวนำเข้าต้องไล่ตามลำดับนี้

```
customer_code  →  tax_id  →  company_name
```

**ทำไม `tax_id` ถึงเป็นช่องสีเหลือง ไม่ใช่ `customer_code`** — จากข้อมูลจริงในฐานข้อมูล ณ ตอนที่ทำเทมเพลตนี้
ลูกค้า 31 รายมี `customer_code` แค่ 4 ราย แต่มี `tax_id` ถึง 26 ราย ถ้ายึด `customer_code`
เป็นกุญแจหลัก แถวที่อ้างถึงลูกค้าเดิมจะจับคู่ไม่ได้เป็นส่วนใหญ่

## ข้อจำกัดที่ควรรู้

- **ฐานข้อมูลไม่ว่าง** — ณ ตอนที่ทำเทมเพลตนี้มี ลูกค้า 31 / ผู้ติดต่อ 6 / ไซต์งาน 8 / Asset 62 / สัญญา 4 อยู่แล้ว การนำเข้าจึงต้องตัดสินใจเรื่องข้อมูลซ้ำก่อนเสมอ
- **ทั้ง `customer_code` และ `tax_id` ไม่มี unique constraint ในฐานข้อมูล** — ระบบไม่กันซ้ำให้ ถ้าซ้ำ ไฟล์อื่นจะจับคู่ได้บริษัทผิดตัว ควรเช็กด้วย conditional formatting ในไฟล์ลูกค้าก่อนนำเข้า
- **`technician_name` ต้องสะกดตรงเป๊ะ** — ช่างในระบบบางคนมีแต่ชื่อไม่มีนามสกุล (เช่น `ธนวัฒน์`, `อธิพันธุ์`) บางคนมีเต็ม (เช่น `เฉลิมเกียรติ ศรีสว่าง`)
- **ผู้ติดต่อ 1 คนผูกได้ 1 บริษัทผ่านเทมเพลต** — ฐานข้อมูลรองรับหลายบริษัทผ่านตาราง `contact_companies` แต่แอปยังใช้แค่บริษัทหลัก (`contacts.company_id`) เทมเพลตจึงทำตามนั้น ถ้าต้องผูกหลายบริษัทให้เพิ่มในแอปทีหลัง
- **`tags` ของลูกค้าเป็น text[]** — ในไฟล์กรอกเป็นข้อความคั่นด้วยจุลภาค ตัวนำเข้าต้องแยกเองแล้วตัดค่าซ้ำออก

## สิ่งที่ระบบเติมให้เอง (ไม่มีในเทมเพลต)

- **รหัส Asset** `AS-0001`, `AS-0002`, … — trigger `set_equipment_code` ออกให้ตอน insert
- **`service_contracts.end_date`** — คำนวณจาก `start_date + (duration_years × 12)` เดือน
- **`service_visits`** — รอบเข้าบริการ สร้างเท่ากับ `frequency_per_year × duration_years` รอบ ห่างกันรอบละ `12 ÷ frequency_per_year` เดือน นับจาก `start_date`

  ตัวอย่าง: 2 ครั้ง/ปี × 5 ปี = 10 รอบ ห่างกันรอบละ 6 เดือน

## แปลงจาก Venio

ถ้ามีไฟล์ export จาก Venio (ชีต `Customers-Venio-V2` / `Contacts-Venio-V2` / `Locations-Venio-V2`)
ไม่ต้องกรอกเทมเพลตเอง ใช้ตัวแปลงได้เลย

```bash
node scripts/convert-venio.mjs "import-data/<ไฟล์ Venio>.xlsx"
```

ได้ออกมา 3 ไฟล์ในโฟลเดอร์เดียวกัน — `venio-1-companies.xlsx`, `venio-2-contacts.xlsx`,
`venio-3-sites.xlsx` — หน้าตาเหมือนเทมเพลตเปล่าทุกอย่าง แค่มีแถวข้อมูลอยู่แล้ว ตรวจแล้วนำเข้าได้เลย

การจับคู่ฟิลด์

| Venio | ปลายทาง |
| --- | --- |
| Customer Code / Customer Name / Tax ID | `customer_code` / `name` / `tax_id` |
| Customer Group + Interested in + Classification | `tags` (Classification เติมคำว่า `Class` นำหน้า เพราะ `B` เดี่ยวๆ อ่านไม่รู้เรื่อง) |
| Mobile (ถ้าไม่มีใช้ Telephone) | `phone` — อีกเบอร์เก็บใน `notes` |
| Location ที่เป็น Billing ของลูกค้ารายนั้น | `address` ของลูกค้า |
| Address + Subdistrict + District + Province + Zipcode | `address` ของไซต์ |
| Latitude / Longitude | `map_url` เป็นลิงก์ Google Maps |
| Contact Name | `first_name` + `last_name` (ตัดคำนำหน้าอังกฤษ Mr./K' ออก ส่วน "คุณ" ที่ติดกับชื่อคงไว้) |
| Position | `title` |
| State, Type, Lead State, Status, Alias, Source, Staff Owner, Referral, ภาค, จังหวัด, Fax, Maps link, Note, Branch Code, Location Type | `notes` เป็นบรรทัดที่มีป้ายกำกับ |

สิ่งที่ตัวแปลงตัดสินใจให้ และย้อนได้ถ้าไม่ชอบ

- **`Bangchak` เขียนเป็น `BCP`** เพราะเป็นแบรนด์เดียวกันและ CRM ใช้ `BCP` อยู่แล้ว ถ้าเก็บทั้งสองแบบ แท็กจะแตกเป็นสองอัน — แก้ที่ `TAG_ALIASES` ใน `scripts/convert-venio.mjs`
- **ที่อยู่ที่ลงท้ายด้วยจังหวัด/รหัสไปรษณีย์อยู่แล้ว จะถูกตัดส่วนท้ายออกก่อนต่อใหม่** ให้เรียงเป็น ตำบล → อำเภอ → จังหวัด → รหัสไปรษณีย์ (ถ้าต่อดื้อๆ จะได้ `...เชียงใหม่ 50300 ช้างเผือก เมืองเชียงใหม่`)
- **ไซต์ชื่อซ้ำภายใต้ลูกค้าเดียวกัน จะถูกเติมชื่ออำเภอในวงเล็บ** ไม่งั้นตัวนำเข้าจะมองว่าเป็นไซต์เดียวกันแล้วทับกัน
- **`industry` ปล่อยว่าง** เพราะ Venio ไม่มีฟิลด์นี้ตรงๆ ข้อมูลทำนองนั้นอยู่ในแท็กแล้ว

## วิธีนำเข้า

กรอกไฟล์เสร็จแล้ววางไว้ที่โฟลเดอร์ `import-data/` (gitignored ไว้แล้ว — ห้าม commit ข้อมูลลูกค้าจริง) จากนั้น

```bash
node scripts/backup.mjs                      # 1. สำรองข้อมูลก่อนเสมอ
node scripts/import-xlsx.mjs import-data/    # 2. ทดลอง — ยังไม่เขียนอะไร
node scripts/import-xlsx.mjs import-data/ --apply   # 3. เขียนจริง
```

ใส่เป็นไฟล์เดียวก็ได้ (`node scripts/import-xlsx.mjs import-data/companies.xlsx`) ระบุทั้งโฟลเดอร์
จะเรียงลำดับนำเข้าให้เองตามลำดับ 1–5 ข้างบน

พฤติกรรมสำคัญ

- **ดูจากหัวคอลัมน์ ไม่ได้ดูจากชื่อไฟล์** — ตั้งชื่อไฟล์อะไรก็ได้
- **แถวที่ตรงกับของเดิม = อัปเดตทับ ไม่สร้างซ้ำ** ลำดับการหาของเดิมเหมือนลำดับจับคู่ลูกค้า
- **ช่องที่เว้นว่าง = ไม่แตะของเดิม** ไม่ได้ล้างค่าที่มีอยู่ให้เป็นว่าง จึงกรอกมาเฉพาะช่องที่อยากอัปเดตได้
- **โหมดทดลองเป็นค่าเริ่มต้น** และจะจำลองแถวที่ "จะเพิ่ม" ไว้ด้วย ไฟล์ Asset จึงมองเห็นไซต์ที่ไฟล์ไซต์งานยังไม่ได้สร้างจริง — preview จึงไล่ได้ครบทั้งสาย
- **กลุ่ม Asset สร้างให้อัตโนมัติ** ถ้า `group_name` ยังไม่มีในไซต์นั้น
- **แถวไหนมีปัญหาจะถูกข้ามพร้อมบอกเหตุผล** แถวอื่นเดินต่อ
- **สองแถวที่ชี้ไปรายการเดิมอันเดียวกัน จะถูกจับได้และข้ามแถวหลัง** ไม่งั้นแถวหลังจะทับแถวแรกเงียบๆ
- **ถ้าอัปเดตแล้วชื่อจะเปลี่ยน จะเตือนให้เห็นก่อน** เช่นจับคู่ด้วย tax_id แล้วชื่อในไฟล์กับในระบบไม่เหมือนกัน
- **ไฟล์ที่หัวคอลัมน์ไม่ตรงเทมเพลตไหนเลยจะถูกข้าม** ไม่นับเป็นข้อผิดพลาด (ไฟล์ต้นทาง Venio ที่วางไว้โฟลเดอร์เดียวกันก็จะขึ้นแบบนี้)

สิ่งที่ตัวนำเข้าจัดการให้

- แปลงชื่อเป็น UUID: ลูกค้า, `site_name`, `contact_name`, `technician_name`, `group_name`
- แยก `tags` จากข้อความคั่นจุลภาคเป็น array แล้วตัดค่าซ้ำ
- คำนวณ `end_date` และสร้าง `service_visits` ให้สัญญาแต่ละฉบับ (ถ้าอัปเดตสัญญาเดิมแล้วตารางเปลี่ยน จะสร้างเฉพาะรอบที่ยัง `pending` ใหม่ รอบที่ทำไปแล้วไม่ถูกแตะ)

ยังไม่มีหน้าอัปโหลดในแอป — ตอนนี้นำเข้าผ่านสคริปต์อย่างเดียว

## แก้ไขเทมเพลต

อย่าแก้ไฟล์ `.xlsx` ตรงๆ — แก้ที่ spec แล้วสร้างใหม่

```bash
node scripts/gen-import-templates.mjs
```

สเปกคอลัมน์ (ชื่อหัวคอลัมน์ ค่าที่ยอมรับ ตัวอย่าง คำอธิบาย) อยู่ที่
[`scripts/import-schema.mjs`](../scripts/import-schema.mjs) แก้ที่เดียวแล้วทั้งสามชีตอัปเดตตาม
และตัวนำเข้ากับตัวแปลง Venio ก็อ่านจากสเปกเดียวกัน จึงไม่มีทางหลุดกัน

สคริปต์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
| --- | --- |
| `scripts/import-schema.mjs` | นิยามคอลัมน์ทั้ง 5 เทมเพลต — แหล่งความจริงเดียว |
| `scripts/xlsx-read.mjs` / `scripts/xlsx-write.mjs` | อ่าน/เขียน .xlsx เอง ไม่พึ่ง dependency |
| `scripts/import-workbook.mjs` | ประกอบ 3 ชีตจากสเปก (เปล่าหรือมีข้อมูลก็ได้) |
| `scripts/gen-import-templates.mjs` | สร้างเทมเพลตเปล่า |
| `scripts/convert-venio.mjs` | แปลง export ของ Venio ลงเทมเพลต |
| `scripts/import-xlsx.mjs` | นำเข้าจริง |
